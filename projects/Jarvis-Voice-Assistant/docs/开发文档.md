## 研究结论摘要

### 人设系统 (参考 OpenClaw, Claude Code)

1. **人设与操作指令分离** - 分成独立文件，便于维护
2. **Markdown 文件作为 Skill** - 主流扩展模式
3. **分层加载** - 可节省 94% token 成本

### 记忆系统 (参考 0GMem, ReMe, SimpleMem)

1. **文件系统记忆** - Markdown 文件，人类可读可编辑
2. **双层架构** - 短期(对话) + 长期(按日期归档)
3. **记忆摘要** - LLM 定期生成摘要注入人设

### AHK 桌面自动化 (参考 Nexus, LLM-AutoHotkey-Assistant)

1. **两层架构可行** - 动作集 + 对象集
2. **Win32 API 优先** - 比发送按键更可靠
3. **结合 LLM 增强** - 自然语言命令解析

## 2. 状态机设计 (三状态)

```
┌──────────────────────────────────────────────────────────────────┐
│                    Jarvis 小圆点状态机                           │
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│  ┌──────┐        左键单击         ┌──────┐                       │
│  │ 闲置 │ ─────────────────────→│ 监听 │                       │
│  │ OFF  │←──────────────────────│ ON   │                       │
│  └──────┘                       └──────┘                       │
│      ↑                                │                         │
│      │         左键单击               │ 按住 CAPS               │
│      │                                ↓                         │
│      │                         ┌────────────┐                   │
│      └─────────────────────────│  语音上屏  │                   │
│                                │ (光标焦点) │←──── 松开 CAPS    │
│                                └────────────┘                   │
└──────────────────────────────────────────────────────────────────┘
```

| 状态 | 触发 | 行为 |
|------|------|------|
| 闲置 (OFF) | - | 释放麦克风，不响应 |
| 监听 (ON) | 左键单击 | 麦克风持续监听，语音→STT→LLM→TTS 实时交互 |
| 语音上屏 | 按住 CAPS | 语音→STT→文字→上屏到光标焦点 (不过 LLM) |

## 3. 人设系统设计 (基于研究优化)

### 3.1 文件结构

```
personality/
├── 01_BASE.md        # 基础身份 (名字、角色、定位)
├── 02_STYLE.md       # 对话风格 (简洁/活泼/正式)
├── 03_CAPABILITIES.md # 能力边界 (能做什么、不能做什么)
├── 04_MEMORY.md      # 记忆摘要 (由记忆系统动态更新)
└── 05_EXAMPLES.md    # 对话示例 (few-shot)
```

### 3.2 设计原则

1. **职责单一** - 每个文件只负责一个维度
2. **Markdown 格式** - 便于阅读和编辑
3. **动态注入** - 记忆摘要由系统自动生成更新
4. **分层加载** - 根据上下文选择性加载，节省 token

## 4. 记忆系统设计 (基于 0GMem/ReMe 研究)

### 4.1 架构设计

```
┌─────────────────────────────────────────────────────────────────┐
│                       记忆系统                                   │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│  短期记忆 (Short-term)                                          │
│  ├── 存储: memory/short_term.json                              │
│  ├── 内容: 最近 N 轮对话 (默认 10 轮)                           │
│  ├── 生命周期: 每次对话后更新                                   │
│  └── 用途: 构建 LLM 上下文                                     │
│                                                                  │
│  长期记忆 (Long-term)                                           │
│  ├── 存储: memory/daily/YYYY-MM-DD.md (按天归档)               │
│  ├── 内容: 当天的对话摘要 + 重要信息                            │
│  ├── 生命周期: 永久保存                                         │
│  └── 用途: 跨会话记忆检索                                      │
│                                                                  │
│  记忆摘要 (Summary)                                             │
│  ├── 存储: personality/04_MEMORY.md                            │
│  ├── 内容: LLM 生成的用户偏好 + 重要事项                       │
│  ├── 更新: 每天/每次长对话后                                   │
│  └── 用途: 注入人设系统                                        │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 文件格式

```json
// short_term.json
{
  "updated_at": "2026-03-23 10:30:00",
  "turns": [
    {"role": "user", "content": "打开微信", "time": "10:30:00"},
    {"role": "assistant", "content": "已打开微信", "time": "10:30:02"}
  ]
}
```

```markdown
# 2026-03-23 记忆

## 对话摘要
- 用户今天主要在开发 Jarvis 系统
- 用户偏好使用 DeepSeek 作为 LLM
- 用户关注记忆系统的设计

## 重要信息
- 用户希望 Jarvis 能记住他的偏好
- 用户不喜欢每次都问"还需要做别的吗"
```

### 4.3 检索策略 (参考 0GMem)

1. **最近优先** - 默认加载最近的短期记忆
2. **按需检索** - LLM 判断需要时检索长期记忆
3. **摘要注入** - 关键信息摘要持续注入人设

## 5. AHK 执行模块 (两层设计)

### 5.1 架构

```
Layer 1: 动作集 (穷举 ~30个系统动作)
Layer 2: 对象集 (动态扫描软件/文件)
```

### 5.2 动作列表

```json
{
  "actions": [
    "打开", "关闭", "最大化", "最小化", "还原",
    "上移", "下移", "左移", "右移",
    "截图", "录屏", "锁屏", "关机", "重启",
    "音量加", "音量减", "静音",
    "亮度加", "亮度减",
    "上一首", "下一首", "播放", "暂停"
  ]
}
```

### 5.3 对象扫描

| 扫描源 | 说明 |
|--------|------|
| 注册表 | HKLM/HKCU Uninstall |
| Program Files | 64位/32位软件 |
| 用户目录 | %APPDATA% 绿色版软件 |
